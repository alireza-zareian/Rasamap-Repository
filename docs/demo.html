❓ سؤال‌های هیئت داوران
چرا SQLite به‌جای PostgreSQL؟
پروژه single-instance + thesis demo. SQLite با Prisma 7 driver adapter zero-latency query داره. پله‌بعدی: تغییر DATABASE_URL کافیه.
امنیت چطوره؟ XSS؟ CSRF؟
JWT در HttpOnly cookie — JS دسترسی نداره. SameSite=Strict جلوی CSRF رو می‌گیره. Zod روی همه ورودی‌ها. Rate-limit sliding-window. Generic error message در auth — no user enumeration.
چرا Next.js 16 / App Router؟
Server Components + API Routes در یک repo. Proxy (middleware جدید) احراز هویت رو مرکزی می‌کنه. ISR برای صفحه‌های استاتیک.
داده‌ها از کجا میان؟
Python scraper (bs4 + lxml) → billboards.json → Prisma seed → SQLite. GitHub Actions شبانه اجرا می‌شه. Neshan API برای geocoding.
user auth چرا phone-based؟
بازار ایران. موبایل unique identifier شناخته‌شده‌تر از email. OTP آینده: تنها فیلد schema تغییر می‌کنه.
overlap check چطور جلوی double-booking رو می‌گیره؟
startDate < other.endDate AND endDate > other.startDate — overlap کامل interval. در DB با index روی [billboardId, startDate, endDate].
مقیاس‌پذیری؟
Rate limiter و audit log الان in-memory — Phase 8 migrate به DB. برای multi-instance: Redis. اما ۲۸۰۰+ billboard روی SQLite با sub-10ms query جواب می‌ده.

لایهانتخابدلیل انتخاب — آنچه در دفاع مهم است
Framework Next.js 16 · React 19 · App Router SSR + CSR + API routes یکجا. Server Components بار JS client رو کم می‌کنه. Proxy (middleware) احراز هویت مرکزی.
Database SQLite · Prisma 7 · better-sqlite3 Zero-latency برای single-server. Schema migration با Prisma. Driver adapter جدید Prisma 7 برای sync driver.
Auth JWT · jose · bcrypt cost=12 Stateless sessions. HttpOnly+SameSite=Strict ← XSS/CSRF safe. RBAC چهارسطحی. Timing-safe dummy hash.
Maps Leaflet 1.9 · Neshan geocoding Open-source · CDN tiles · Marker clustering. Neshan API ایرانی برای geocode آدرس فارسی به lat/lng.
Validation Zod · .safeParse() Type-safe schema validation روی همه API inputs. هرگز parse() نمی‌زنیم — کرش نمی‌کنه.
Scraper Python 3 · bs4 · lxml · GitHub Actions جدا از Next.js process. ۴ worker concurrent. Nightly cron → commit JSON → seed → SQLite.

سؤالات احتمالی داور
؟ «داده‌ها از کجا می‌آیند؟» ◀
پاسخ: یک scraper Python نوشتیم که از Divar و Sheypoor داده جمع‌آوری کرد. نتیجه ۳۵۳۶ بیلبورد واقعی ایرانی در SQLite ذخیره شده. مختصات جغرافیایی با Neshan API geocode شدند.
؟ «ترافیک چطور محاسبه می‌شود؟» ◀
پاسخ: فعلاً یک heuristic ساده بر اساس نوع رسانه، موقعیت، و قیمت است. API واقعی ترافیک (مثلاً Neshan Traffic) در roadmap آینده دارد — صادقانه اعلام می‌کنیم این یک تخمین است.
؟ «چرا SQLite؟ چرا PostgreSQL نه؟» ◀
پاسخ: در این مقیاس (چند هزار رکورد، single-server) SQLite کاملاً کافی است و نیاز به سرور جداگانه ندارد. Prisma ORM داریم — migrate به PostgreSQL فقط یک تغییر driver است. برای production scale آماده‌ایم.
؟ «امنیت؟» ◀
لایه‌های امنیتی:
  • JWT در HttpOnly cookie — XSS نمی‌تواند token بدزدد
  • bcrypt با cost 12 — brute force مقاوم
  • Rate limit جداگانه برای login کاربر (۱۰ تلاش/۱۵ دقیقه) و admin
  • Zod روی همه input‌ها — injection غیرممکن
  • RBAC: super_admin → admin → editor → viewer → user
  • Proxy guard: dashboard فقط با session، admin routes فقط admin
؟ «تست دارید؟» ◀
پاسخ صادقانه: تست unit/integration مکتوب نداریم — این یک پروژه thesis بود با timeline فشرده. ولی end-to-end دستی کامل تست شده، و TypeScript strict mode + Zod خطاهای runtime را پوشش می‌دهند. next step بعد از thesis اضافه کردن Playwright e2e test است.
